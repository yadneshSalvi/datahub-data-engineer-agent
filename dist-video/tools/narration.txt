Every company runs on data pipelines. Raw tables feed cleaned tables, which feed the dashboards that executives actually read. DataHub is an open source catalog that maps all of it. Every table, every column, every pipeline. And it tracks whether the data is healthy.

So when a dashboard goes wrong at two in the morning, someone gets paged, opens that map, and walks it by hand, table by table, for hours. That is the job we handed to an agent.

This is its control panel. On the right, the catalog snapshot. Twenty three assets in a ride hailing warehouse, every one of them healthy. On the left, the signal inbox, empty. Nothing is broken yet.

Now we stage a real failure. An ingestion job stalls, and the inbox fills up. Each row here is a failing assertion. An assertion is simply an automated data quality check that DataHub runs against a table.

Look at the top row. A table called agg daily rides has collapsed to four rows. Its check expected at least twenty five. One click, and the agent takes the page.

It starts with memory. It searches DataHub for post mortems it has written about this table before. Nothing yet. This is the first time it has seen this one.

Then it walks the lineage. Lineage is the map of which tables feed which, and the agent climbs it upward, one hop at a time. At every table it checks what a human would. Is the check passing. Is the data fresh. Did the row count collapse.

Watch the graph on the right. Staging trips is broken, but its parent is worse, so it keeps climbing. And it stops at trips raw. Twenty six hours stale, against a six hour freshness limit, with nothing feeding it. That is the root cause.

Then it works downstream, to see who this actually hurts. Fifteen assets, ranked by real usage. And it acts inside DataHub. It files an incident. It tags the root cause, down to the column. It notifies the owners. And it writes a post mortem back into the catalog.

Now a different table breaks, three hops away, one this agent has never triaged. Watch the first card. It remembers. It finds the post mortem it wrote, confirms it against live evidence, and goes straight to the answer.

Same root cause. Same answer. A fraction of the work. Every incident it closes makes the next one faster, because the knowledge lives in DataHub, where the next engineer will find it too.
